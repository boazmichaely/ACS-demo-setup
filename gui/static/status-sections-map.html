Status folds: field → UI map

This page is an annotated mock of the live Status card. Yellow chips name the JSON field (or summary-line field) that produced each piece of UI. Use it while you edit emit_status_sections() in a module: match the chip to the key in your jq object, then look at the pixel it labels.

The module header row (id, state badge, message) comes from the tab-separated values (TSV) summary line that --status must also print: three fields separated by a single tab character (id, state, message). Everything under that header comes from ACS_SECTIONS_JSON / sections[], not from the TSV line.

Field Where it shows
group Small uppercase heading above a batch of folds. Printed only when the value changes from the previous section item. Same group on several items keeps them under one heading.
title Main label on the fold’s closed row (the thing you click to expand).
summary Muted text on the right of that same closed row (one-line hint).
tag / tagLabel Optional badge left of title. tag picks color (ok/ready, error/fail, else warn). tagLabel is the visible text (falls back to tag).
body Content inside the expanded fold.
bodyFormat How body is rendered. prose (default) = normal text (newlines become line breaks). json = pretty-printed monospace block (pass an object/array, or a JSON string).
